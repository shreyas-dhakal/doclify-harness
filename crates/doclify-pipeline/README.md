# Capture and extraction integration

`doclify_capture::queue::Queue::open` takes an ignored, repository-local state directory (for example `<git-common-dir>/doclify/processing`). Invoke `drain_hooks(&repo.queue_dir())` in a background worker; hook files are removed only after their jobs and transcript checkpoints are durable. A caller can also feed discovered sessions to `reconcile` using the same hook envelope, with `agent`, `payload.session_id`, and `payload.transcript_path`. The caller must restrict discovery to the registered repository and serialize workers for that repository. Errors, including unsupported transcript records, must be surfaced in status and retried; a partial final line waits for the next scan.

Implement `doclify_pipeline::Extractor` using the selected model bridge and call `process` with a separate ignored output directory. Outputs are durable JSON proposals keyed by capture job ID; validate them against the domain schema and explicitly propose them through the domain store, never accept them automatically. Extraction output is retained after acknowledgement, so a downstream importer needs its own idempotent checkpoint. Provider wiring, periodic scheduling, transcript discovery, status reporting, and domain import are integration work for the application; this crate does not perform those operations itself. Serialize calls to `process` as well as reconciliation, and keep state directories private because they contain raw transcripts.
