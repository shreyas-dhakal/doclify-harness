# Capture and extraction integration

`ApiExtractor` connects a configured `doclify_model_bridge::providers::ApiProvider` and model to `process_proposals`. Each queued job is supplied as `{source_id, event}`; proposals may cite only that `event:<job-id>` identifier. The model response is semantically validated, saved durably in an ignored private output directory, and converted to domain records in the proposed state. Records use deterministic `capture-<job-id>-<index>` IDs. An existing identical first version is reused, including after review; conflicting records fail closed. A job is acknowledged only after all proposals are stored. Provider, validation, and storage errors leave it pending for retry. Output is retained and reused after a crash, so use a separate output directory from the legacy `process` API and do not alter saved results.

`run_once` drains hooks, reconciles supplied session roots, and processes queued proposals. `spawn_worker` runs this iteration on a background thread, returns per-iteration results on a channel, and retries after the supplied interval; call `Worker::stop` to stop and join it. The application must consume and surface errors and use the same queue root for all workers for a repository; iterations acquire an exclusive cross-process queue lock. State contains raw transcripts and must be private and ignored by Git. The bridge's API provider performs blocking network requests; configure credentials and model explicitly. No proposal is automatically accepted.

`discover_sessions` recursively scans supplied Codex or Claude roots without following symlinks and reconciles JSONL sessions whose first complete record supplies a session ID and a working directory within the canonical repository root. Sessions with missing or unrecognized first-record metadata are skipped; discovery does not infer repository ownership from filenames, and it does not include separate worktrees outside that root. Hooks continue to capture sessions independently. Transcript adapters report unsupported records as errors, and partial final lines wait for a later scan. The caller chooses trusted transcript roots; hook transcript paths must fall within one of those roots and cannot escape it through symlinks.

`SelectedExtractor` selects an API or constrained CLI explicitly. Construct `CliExtractor` with `Bridge::claude` or `Bridge::codex`, an optional model, and a timeout; invoke this synchronous adapter only on a blocking worker outside a Tokio runtime. CLI output is schema-checked and semantically validated before the existing citation and durable import checks. Errors do not fall back to another provider and leave the queue pending. Claude subprocesses receive the capture-suppression environment marker and request no session persistence; Codex remains unavailable because its advertised read-only sandbox does not prove tools are disabled. CLI authentication and effective enforcement require separate live verification.

Root authorization alone does not establish transcript ownership. Use `run_once`, or hold the queue lock and call `reconcile_repository_locked`, to validate transcript metadata against the worktree before importing hooks. The caller must use one worktree-local queue, hook directory, output directory, and store together. Malformed and unauthorized hooks are retained under the hook directory’s `rejected` subdirectory so later hooks can proceed.
