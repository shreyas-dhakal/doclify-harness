# REPL integration

`doclify::repl` is a library module ready for the binary's interactive loop. For a non-slash input, load the selected model JSON with the existing `load_config`, build bounded repository context with `doclify_context::build`, and call `doclify::repl::request(&config, line, context_text)`. Display the answer and each proposal with its evidence and `proposed` review state; surface errors to the user. The helper never writes or accepts records. To make proposals durable, explicitly map them into the domain store as proposed records with appropriate provenance and unique IDs; do not call the acceptance path without a separate human review command. Evidence identifiers supplied to the model must appear in the context string, or the adapter rejects the response.

For API model selection, call `discover_models(&config)` and filter the returned IDs with `filter_models(&models, query)`; the latter is case-insensitive. Selecting an ID should save the same provider, base URL, and key environment variable with the new model ID through the existing config writer. Report discovery errors rather than treating configured model names as confirmed available. CLI providers are selected by their existing `claude`/`codex` names; the bridge independently checks whether constrained execution is available.

The provider request sends the selected context to the configured service. No automatic persistence, acceptance, or mutation of documentation happens in this module.
