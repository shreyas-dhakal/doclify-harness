## Prioritized actionable checklist

- [ ] **P0 — Make changes to existing claims versioned proposals.** Extraction always assigns `capture-{event-id}-{index}`, version 1, and `supersedes: None` (`crates/doclify-pipeline/src/lib.rs:181-216`); neither schema nor prompt identifies an existing record (`model-bridge/src/providers.rs:13-24,46-49`). Subsequent contradictory or revised evidence becomes a separate proposal rather than a reviewable new version, so accepted old guidance can coexist with a newly accepted conflicting decision. Domain history supports versions (`crates/doclify-domain/src/lib.rs:142-179`), but its unit tests manually construct them (`crates/doclify-domain/tests/records.rs:24,146`). Add identity matching with explicit review, retain old accepted version until replacement, and integration-test change/reject/accept/reversion across sessions.
- [ ] **P0 — Deliver all applicable shared records in linked worktrees.** `session_context` falls back to the primary worktree only if `build` returns `None` (`crates/doclify-capture/src/hook.rs:55-63`); a linked worktree with any local record yields context and hides every primary accepted constraint. Merge or share record stores with deterministic conflict handling and test primary accepted constraint plus unrelated local proposal/constraint. Current linked-worktree test covers empty-local fallback (`crates/doclify-capture/tests/hook_cli.rs:213`; README acknowledges fallback behavior).
- [ ] **P0 — Prove and enable both agent integrations end to end.** Codex inference deliberately fails closed (`model-bridge/src/lib.rs:56-64`); Claude capability probes help text, not actual enforcement/authentication (`:65-104`). Guest checkout E2E uses synthetic transcripts, fake provider and manually invoked hook (`crates/doclify/tests/e2e.rs:291,355`; `README.md` Validation). Validate real supported versions, hook formats and constrained execution with opt-in authenticated tests, then run the actual Codex capture → review → Claude startup handover. Keep Codex disabled until restrictions are verifiable.
- [ ] **P1 — Capture tool results and accurately track test freshness.** Installer registers only SessionStart, UserPromptSubmit, Stop and SubagentStop (`crates/doclify-capture/src/install.rs:20,102-113`), but observed test detection requires PostToolUse (`crates/doclify-evidence/src/verify.rs:80-107`); transcript-backed hooks also enqueue transcript entries instead of hook payloads (`crates/doclify-capture/src/queue.rs:120-132`). Existing evidence test injects synthetic PostToolUse directly (`crates/doclify-evidence/tests/evidence.rs:245-250`). Wire real tool events/results through the integrated path. Capture working-tree state: `mark_stale` compares only commits (`verify.rs:153-175`) while docs explicitly admit uncommitted changes were not captured (`docs.rs:321-323`); avoid describing a run on a dirty tree as evidence for clean HEAD, and test changes before and after execution.
- [ ] **P1 — Preserve experiment outcome and update lifecycle.** Proposal schema has no experiment outcome (`model-bridge/src/providers.rs:13-24,46-47`) and importer sets it to `None` (`crates/doclify-pipeline/src/lib.rs:204`); abandoned/active/completed experiments cannot be extracted, and abandoned exclusions rely on manually constructed records (`crates/doclify-context/src/lib.rs:115-128`; `tests/context.rs:130`). Add validated outcome and revision mapping with integrated tests.
- [ ] **P1 — Recover unsupported formats without silently stranding work.** An unsupported transcript returns InvalidData (`crates/doclify-capture/src/queue.rs:113-118`); reconciliation moves the hook into `rejected` (`crates/doclify-pipeline/src/lib.rs:397-408`), while discovery may rediscover it. Status counts rejected files (`crates/doclify/src/main.rs:117-119`) but provides no reason or retry operation, and a no-longer-discoverable session may stay stranded after adapter repair. Provide actionable reason, replay and tests for eventual recovery, including unsupported lines followed by valid entries.
- [ ] **P1 — Implement scope and parent-session attribution.** Records contain no repository/branch/path scope (`crates/doclify-domain/src/lib.rs:49-62`); handover explicitly treats all constraints repository-wide and only ranks by text (`crates/doclify-context/src/lib.rs:12-13,321-334`). Parent sessions are not implemented (`crates/doclify-capture/README.md:26`). Persist and apply scope; on unknown task/path include only repository-wide constraints plus pointers, with multi-worktree, branch and child-session tests.
- [ ] **P1 — Make hook installation/diagnostics truthful.** `add_ours` silently returns if `hooks` is not an object and skips an event if its value is not an array (`crates/doclify-capture/src/install.rs:102-113`), yet init reports success (`crates/doclify/src/main.rs:91-96`); registration precedes both edits and is left behind on a later failure (`install.rs:41-54`). Validate structures before mutation, report partial failures and make registration transactional. Doctor tests only config-file existence, not entries, versions, auth or actual compatibility (`crates/doclify/src/main.rs:194-202`). Add accurate checks and remediation.
- [ ] **P1 — Fix model picker completeness and status.** `/model` always starts with literal `claude` and `codex`, with no capability/auth status, and extends only remotely discovered models (`crates/doclify/src/main.rs:345-350`); a configured API model disappears on discovery failure. Model list reports capability separately (`:492-509`), but picker does not. Include configured ID, distinguish unavailable/unverified and do not imply executable availability; test offline discovery and disabled bridge.
- [ ] **P1 — Ensure provenance is portable and links actionable.** Extracted citations are local `event:<id>` (`crates/doclify-pipeline/src/lib.rs:145-165,205-214`); fallback excerpt is optional and event files live in ignored local storage. Viewer displays evidence IDs as `<code>` rather than links (`viewer/web/src/main.tsx:105-110`). Require a bounded genuine source excerpt when needed, resolve citations in viewer, and verify a fresh clone can inspect evidence without raw transcripts.
- [ ] **P1 — Preserve prose through concurrent regeneration.** Viewer serializes its own saves with a docs-directory lock (`viewer/src/lib.rs:129-158`); generator's reconciliation uses separate file operations (`crates/doclify-evidence/src/docs.rs:81-147`), so a generator write racing after the second revision check can overwrite a just-saved edit. Use a shared lock/atomic compare-and-swap across generator and viewer and test concurrent save vs sync. Existing concurrent save test covers two viewer requests only (`viewer/tests/security.rs:183`).
- [ ] **P2 — Complete local product measurement.** No implementation of capture coverage, review corrections, handover delivery or repeated-explanation measurement was found; status is counts/errors (`crates/doclify/src/main.rs:99-120`). Add local-only opt-in measurements tied to acceptance, no hosted telemetry.
- [ ] **P2 — Close packaging and interaction gaps.** `doclify docs` is special-cased before JSON command handling (`crates/doclify/src/main.rs:68-70`), so not every noninteractive command emits machine-readable JSON. `init` installs hooks and creates store but does not configure model (`:91-96`); setup requires separate command. Verify macOS/Linux releases and packaged viewer, improve setup and give docs a machine-readable mode. SQLite search index is absent; browser loads all docs and filters client-side (`viewer/web/src/main.tsx:52,79`); determine whether scale requires the plan's rebuildable index.
