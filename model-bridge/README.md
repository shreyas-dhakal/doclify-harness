# Doclify model bridge foundation

This standalone Rust library invokes Claude Code in noninteractive print mode with built-in tools disabled, restricted and safe modes, strict MCP configuration, no persisted session, no slash commands and no interactive permission grants. It sends the prompt over stdin and validates the structured response locally against the caller's JSON Schema. The process receives `DOCLIFY_GENERATED_SESSION=1` and `DOCLIFY_BRIDGE=1`; capture hooks suppress bridge-generated events. Safe mode and no session persistence also reduce recursive capture.

`Bridge::capability` checks the installed executable's help for the required flags; `ConstrainedAuthenticationUnverified` means only that the CLI advertises them, not that authentication, model availability, actual runtime enforcement, or managed policy compatibility were verified. The installed versions inspected were Claude Code 2.1.308 and codex-cli 0.166.0. Claude's managed settings still apply even in safe mode; users must trust the CLI and its administrator policy. No authenticated inference was run. Codex is deliberately unavailable and is never spawned. Evidence from codex-cli 0.166.0 local help: `codex exec --help` offers no option to disable tools, and `--sandbox` "select[s] the sandbox policy to use when executing model-generated shell commands" only. Rendering the model-visible input with `codex debug prompt-input` under an empty `CODEX_HOME` (no credentials) and `--disable shell_tool --disable unified_exec --disable code_mode_host --disable sleep_tool` still lists `functions.exec` (a JavaScript tool whose nested tools include `apply_patch`, `view_image` and MCP resource readers), `functions.request_user_input`, and `collaboration.spawn_agent`. No objectively verifiable tool restriction exists, so the bridge fails closed. Do not silently fall back to another provider.

`Bridge::execute` returns structured errors including exit status and stderr (which may contain sensitive information). Callers should retain their pending work on errors and control logging of diagnostics. A timeout kills the direct child; external CLI descendants are not guaranteed to terminate. The caller must decide what information may be sent to the selected provider, and must own all documentation writes and review state.

The bridge is a workspace member used by the CLI and pipeline. Run `cargo test -p doclify-model-bridge`; live authenticated smoke tests are intentionally absent.

`providers::ApiProvider` supports OpenAI-compatible chat completions and Anthropic messages, plus provider model-list discovery. Set `base_url` to the provider's versioned API root and `api_key_env` to an environment variable name; the key is read only when making a request. Configured `models` are identifiers supplied by the user, not evidence of availability. Calls are synchronous and should be run on a blocking worker when integrating with Tokio. Redirects are disabled and non-loopback endpoints require HTTPS. Provider errors deliberately omit response bodies and credentials.

`providers::validate_proposals` rejects unknown fields, non-proposed review states, missing citations and unsupported kinds. It does not establish that cited identifiers exist or that a claim is true: the extraction pipeline must validate citations against its source set, retain the input and checkpoint until a validated proposal is durably stored, and require explicit review before acceptance. Neither provider calls nor validation write records, persist checkpoints, or change review state. The CLI bridge accepts a caller-provided schema; the pipeline CLI adapter applies the shared proposal schema and semantic validation. The CLI provides provider configuration and model discovery; authenticated smoke tests remain absent.
