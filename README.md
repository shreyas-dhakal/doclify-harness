# Doclify initial CLI

Build with `cargo build -p doclify` and place `target/debug/doclify` on PATH before running `doclify init` inside a Git repository. Init installs additive Claude Code and Codex hooks; Codex additionally requires project trust and hook approval in its `/hooks` view. `doclify uninstall` removes Doclify hook entries but retains captured data. Hooks fail open and queue events locally in the Git common directory.

`doclify status` reports queued event count and proposals. `doclify review <id> <version> accept|reject|supersede` explicitly reviews the latest proposal; `doclify handoff` emits accepted requirements and decisions with provenance and separately labeled accepted tasks and questions. Outputs are JSON. Running without arguments opens a basic line-oriented REPL with matching slash commands. The domain library currently provides the API for creating proposals; the CLI does not yet extract or create them.

This is an initial slice, not the full plan: queued events are not processed or reconciled, startup hooks do not inject context, and handoff is unbounded and repository-wide with no topic/path relevance. There is no model selection or extraction workflow, Git/GitHub evidence sync, documentation generation, doctor, viewer/editor, or authenticated end-to-end validation. The model bridge is included in the workspace but not exposed through the CLI; Codex inference is unavailable until a constrained mode is verified. Hook registration is per worktree; status reports pending event files but does not validate hook health, malformed events, transcript compatibility, or authentication.
