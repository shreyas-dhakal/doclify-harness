# Doclify viewer

The viewer is integrated into `doclify docs` and `/docs`. Release binaries embed the checked-in production assets; rebuild them with `npm ci --prefix viewer/web && npm run build --prefix viewer/web` before rebuilding Rust when the frontend changes. Debug builds read assets from `viewer/web/dist` at runtime. For direct development, `cargo run --manifest-path viewer/Cargo.toml --example serve -- <repo>` serves a repository. The host must retain the server task while the viewer is in use.

Documents are existing `.md` and `.mdx` files in `docs/doclify`. Nothing in them is executed. `web/src/mdx.ts` splits a document losslessly into blocks: plain Markdown is edited in the rich editor; `Requirement`, `Decision`, `Evidence` and `Question` components with literal string attributes and a plain-Markdown body render as callouts whose body is rich-editable while their tags stay verbatim; code fences, tables, images and reference definitions are rendered but locked; any other JSX, expression, import, export or frontmatter is shown as inert source. Locked and unsupported blocks are written back byte for byte, and untouched editable blocks are not re-serialized. Edited blocks are re-serialized by MDXEditor, so their Markdown spelling may be normalized. Source mode edits everything. Block detection counts tag and brace balance rather than parsing MDX, so an unbalanced block is protected through the end of the file.

Document reads and writes are descriptor-relative: the repository is opened once at launch and each request opens `docs/doclify` and the document's directory beneath it with `cap-std`, so a path component swapped for a symlink cannot reach outside, and a document that is itself a symlink is refused. Saves carry the content hash they were based on. An exclusive `flock` on the `docs/doclify` directory serializes viewer tabs, viewer processes, and documentation regeneration; the hash is checked before writing and again just before the atomic rename, and the directory is synced afterwards. A writer that ignores the lock, such as an editor or `git checkout`, is detected unless it lands between that second check and the rename. A conflicting save returns the latest version, and the page shows both versions with keep-mine, use-latest and merge-in-source choices; nothing is merged automatically. Saving never changes review state.

The review queue lists the latest version of each proposed record; accept, reject and supersede each require confirmation and append a version through the domain store, whose exclusive link rejects a second review of the same version. The records panel shows review and implementation state separately with evidence and provenance; open questions, abandoned experiments, and proposed, rejected or superseded records are labelled as not instructions. The page has a skip link, labelled landmarks and editors, pressed-state mode buttons, focus moved to the opened document and to conflicts, a status live region, and Ctrl/Cmd+S to save.

Run `cargo test --manifest-path viewer/Cargo.toml` for the server tests, and `npm test --prefix viewer/web` for the block-splitting tests and the Playwright browser tests (Chromium, with axe accessibility checks), which build and launch the example server against a temporary repository and use the committed `web/dist` assets. Record reads and reviews go through the path-based domain store. The viewer itself does not regenerate pages; the evidence generator handles regeneration and merges under the same lock. Generated source links open the exact portable record version and excerpt in the viewer; evidence identifiers that match provenance open that source as well. Not provided here: live notification of changes made in other tabs (detected at save), and editing inside unsupported blocks other than in Source mode.

Search uses a disposable SQLite index in `.doclify/local/search.sqlite3` for documentation and the latest record versions. It is rebuilt from local files on each query, including after external edits or cache corruption; the index contains local document and record text and must remain ignored.
